# Feedback on Nebius Token Factory, Sandboxes and NVIDIA Nemotron

Running log kept during the build (2026-10-15 to 2026-10-27). Each item: what we did, what worked, what needs work.

## Onboarding (zero to hello world)
- Billing setup with a bank card is mandatory before the console works at all, including for hackathon promo credits. The card can be charged automatically if the balance goes negative; there is no hard "stop at zero" option, so we built our own spend cap in code. A prepaid-only mode or a hard stop at zero would make promo credits safer for students and hackathon participants.
- The hackathon promo form emails a code within minutes; applying it is a separate step under Top up. On our account the AI Builder Program credits ($29.50) were added automatically as an adjustment, and the separate hackathon code then failed with "Promocode apply limit exceeded" and no further detail. If accounts are limited to one promotion, saying so on the promo form (and in the error) would save confused retries.
- The "what happens when your trial ends" switch is a great safety control ("Stop usage when the trial ends ... your card is never charged"). But choosing it also stops API keys at trial end even when promo balance remains, so a hackathon demo that must stay up through judging has to choose paid usage. A third option, "use remaining credits, then stop", would let builders cap spend at zero card exposure.
- The Structured output docs Python sample is missing commas after `"type": "json_schema"` and after the closing `}` of `response_format`, so it does not run as copied.

## Nemotron models
- JSON-schema output (`response_format: json_schema`): Nemotron 3 Super, Nemotron 3 Ultra and Nemotron 3 Nano returned clean JSON on the first try. Nemotron 3.5 Lightning returned the correct JSON object but appended extra text after it (a stray quote and a repeat of the object), so strict parsers fail; we parse the first complete JSON value and ignore the rest.
- Model IDs are inconsistent in casing and punctuation (`nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B`, `nvidia/Nemotron-3_5-Lightning`, `nvidia/nemotron-3-super-120b-a12b`, `nvidia/Nemotron-3-Ultra-550b-a55b`), and the catalog shows "Nemotron-3.5-Lightning" with a dot while the API ID uses an underscore. Listing `/v1/models` is the only reliable way to get them right.
- Instruction following on optional fields: our planner prompt tells Nemotron 3 Super to add literal expected-output strings only when the tutorial shows them. On a pandas tutorial with no printed output, Super still invented one (`"   name  score"`, with guessed column padding), which made every correct fix fail the check. Same input, same temperature (0.1): one run added it, another did not. We now keep only literals that appear on the page and compare with whitespace collapsed. Lesson for other builders: treat model-written assertions as suggestions and verify them against the source.
- In another run, Super marked a scikit-learn tutorial "not runnable" because `load_boston` was removed, even though the prompt says to preserve and run the code as written. An explicit negative rule ("never mark it not runnable because the code looks outdated") was needed on top of the positive one.
- Dropped content: on a two-block tutorial (an install command plus a Python snippet), Super sometimes returned a plan with only the install step, so the tutorial's code never ran and the run looked healthy. We reproduced it in about 1 of 5 identical calls at temperature 0.1. We now measure how much of the page's code reached the plan and ask once more, naming the missing blocks, when less than half did. Structured output guarantees the shape of the JSON, not that the content is complete.
- Double-escaped strings in structured output: once, Super returned a four-line Python snippet as a single line with literal `\n` sequences inside the JSON string (the escape was applied twice), so a working tutorial failed with a SyntaxError and our repair stage then "fixed" it back. The JSON was valid and matched the schema, so validation could not catch it. We now restore such content when the page itself has the real lines, and never report a fix that only restores the page's own code.
